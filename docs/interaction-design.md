# 交互设计

## 1. 两个入口，不造工作台

- **顶部灵动岛为日常主入口**：原创AppKit无边框non-activating panel＋SwiftUI，compact胶囊显示Pi标识/运行/待输入数，hover或点击后展开真实会话卡片；事件到达不自动展开或抢焦点。刘海屏以safeArea/摄像头空隙避让，普通屏/外接屏用顶部胶囊fallback，不扫描其他App窗口或要求新系统权限。菜单栏作为始终可用的备用入口。
- **独立管理窗口**：左侧“会话 / Token / 重要事项 / 设置”，子任务和计划归入准确会话详情；中间当前对象列表；右侧详情与有来源的状态、管理动作。窗口关闭不退出Pi、不停止工作。
- 设置只包含本App的显示、通知表现、明确接入和现有管理页链接。不提供模型/权限一键降级、全局工具开关或第二套业务策略。

[打开静态合成预览](design/pi-desk-v0.1.html)。预览仅HTML/CSS文档，没有脚本、网络、真实账号或真实管理动作；按钮不可执行。它不是后续技术栈选择，实际App仍为SwiftUI/AppKit。

## 2. 默认视图

默认是“会话”的“在线”筛选；断连卡仅隐藏于默认主列表，仍可在“全部/断连”查看，不停止或删除Pi。搜索、状态、隐藏都作用于`visibleSessions`，主列表与可见计数一致；过滤外对象不继续显示可误操作的详情。紧凑会话行固定高度、长名一行截断并保留完整辅助标签，详情完整；未命名对象以项目及会话短标识区分，本机别名可搜索，用户可主动置顶；子任务操作在主详情折叠，避免堆满空表单。重要事项作为独立入口，不用红色待办把正常空闲和回合结束全部变成待人工处理。

每张会话行以本机别名或会话/项目名为第一层，中文执行状态、当前活动为第二层，项目/模型及真实最近活动时间为次要信息。优先真实待输入，再异常、运行和安静的回合结束；“回合已结束”不叫目标完成。长名截断但可读完整辅助标签。source/epoch/runId/raw协议与coverage原因移入可展开诊断；未知/部分覆盖/断联仍以中文出现在正常层，不抹掉真实性。默认不展示大空白输入框，追加/纠偏在准确卡片旁按需展开，消息始终绑定会话epoch。

选中对象的控制条仅含有真实接线的动作：

| 动作 | 交互含义 | 回执与边界 |
|---|---|---|
| 打开原会话 | 只跳转精确Herdr pane或唯一Terminal.app TTY tab；无route/多匹配/Automation拒绝明确不可定位 | 不按cwd/名称猜窗口，不自动启动第二Pi writer，不假装打开别的窗口成功 |
| 追加要求 | 默认原生follow-up，保留当前工作 | 无原生收据只显示已请求，证实后才标排队，非已完成 |
| 纠偏 | 明确steer，在原生安全边界进入 | 不先杀当前工具再重启 |
| 中止当前回合 | 只请求当前会话abort | 标注不保证停止后续队列/子任务/外部副作用 |
| 停止子任务 | 对准确owner/runId请求stop | 从“请求停止”到owner确认终态，不提前变绿 |
| 恢复子任务 | 保留原任务，由owner验证恢复资格 | 不支持时不退回“新开一个同任务” |
| 暂停计划 | 停未来触发，保留正在执行的工作 | 与停止当前运行分开按钮/说明 |
| 已读/静音 | 改通知表现 | 不代答问题、不改变执行 |

普通动作不追加通用“是否继续”弹框。已有owner硬规则或真实必要决策沿原流程，UI不新造审批；本地明确目标的提交是用户意图，不是为每次自动执行取确认。

## 3. 子任务与计划

侧栏只保留会话、Token、重要事项、设置；子任务与计划固定在准确会话详情中为有数量/空态/覆盖与刷新状态的折叠分区。旧view-state的子任务/计划/未知page迁移为会话，保留筛选与Token偏好。⌘1/⌘2/⌘3导航会话/Token/重要事项，⌘F聚焦搜索；“下一个需关注会话”只轮转本地未读input/failed缓存，不新增owner查询或自动回答。

子任务按父会话分组，显示正在运行/回传中/已结束/未知。独立注册的同一孩子可以被链接，但不复制成两份统计。前台/后台来源不足时显示“关系待核”，不猜父亲。

计划按owner命名空间分组，不按同名合并。缺少在线管理接口时显示“打开原管理入口”，不提供伪按钮或直接写文件。计划历史只用原owner已有运行元数据，不变成会话历史浏览器。

## 4. Token 页面

统计页默认今日，提供近7天/本月/自定义起止日期；跨所有已记录会话。不重复全局标题，时间segmented、来源menu、模型picker和刷新组成ViewThatFits紧凑工具条，自定义日期仅选择后出现；日期/本地时区和更新时间为次要一行。主卡仅一个当前口径的大数字，交互=input+output、缓存=cacheRead+cacheWrite、全部=四桶记录总处理量；下方四桶小拆分保留，不另列重复的大合计或“所选视图+同值”。趋势紧随主卡，图高175pt，主数/趋势/数据表/模型分布同口径；1120×760默认折叠详情时主卡与完整趋势无需滚动，960×620至少保留主数和图主区域。来源差异/计数、已有记录覆盖、导入收据和完整边界默认折叠置于趋势后；模型分布/数据表/会话下钻下移，数据不删。索引错误、未知/未采集、pending和冲突仍有短提示，详情可展开。

“上下文占用”单独展示，不能叫已消耗Token；缺值显示“未知/尚未结算”。时间图表来自持久实时final和2026-10-26授权的一次历史usage元数据补采；实时记录/一次性历史补采/去重合计可切换，来源卡片对齐当前日期与模型，覆盖起点随来源变化，历史收据展示冻结覆盖日期/缺链/未知模型/缺字段等原因。实时与历史重叠沿用原来源、fork复制只计原消费；App启动和刷新不重扫旧日志；未采集日期用空缺/文字而非零柱，部分字段显示已知下界；未来范围无数据不伪称已采集。自定义结束日期早于开始日期时不发查询、不偷偷改成开始当天；保留旧结果和旧范围标签，明确提示修正日期。费用无依据则隐藏金额。

用量对比默认折叠，仅用户展开后沿既有单 utility ledger 顺序读取本期与前一等长日历时段，来源、模型与 metric 保持一致；不让两次查询在合并队列中互相覆盖。只比较双方已结束的前 N 个桶，进行中桶不参与；任一未采集/缺字段/索引错误、结构化采集丢弃/未落盘/写失败、导入跳过或冲突抑制百分比，零基线不算无穷增幅，DST 单日小时数不同时明确不直接比较。主总量/趋势仍为原范围，不用对比子集替换主数。

## 5. 重要事项与治理

重要事项按等待输入、本轮异常、本轮结束后的未查看变化分组。实际input-required优先；其次是任务级失败和需关注异常，再是结果未读。结束提醒要求当前执行证明、真实 settled 事件及无 pending；从需关注筛选打开纯结果时先切到能保留详情的全部视图，自动已查看还要求准确详情实际可见，搜索/运行筛选隐藏的旧选择不清提醒。已查看按 runtime/结束序号隔离，既不代答也不推断业务目标完成。自动重试中显示原因与进度，但不要求点继续。每项写明来源和时间；Gate/CI摘要区分判定head、实际merge及post-CI，不用一个“成功”图标包办。

没有接入的来源保持“未配置/不可用”，不会影响其他会话。没有新需求，不新增AI诊断模型。既有模型建议以“建议”显示，不能覆盖规则。

设置分为 Pi Desk、Pi 原生设置、高级连接三个入口，默认不展开原生配置；原生选项使用中文标签但保存原值。设置页提供Pi原生用户settings.json白名单投影/安全保存（项目overlay只读、冲突/坏JSON/权限/锁只读保全），并提供“开启系统通知”：只有用户显式点击才调用标准系统通知授权；用户是否允许仍由系统提示决定，App不自动点击或启动申请。拒绝/申请失败/发送失败均解释原Pi通知与自动化不受影响；重复点击只保留一个在途申请。

## 6. 空、错与断联

- 空列表：“尚无已接入Pi会话”，提供原扩展加载说明；不扫描历史以填满界面。
- 断联：保留最后更新时间并置stale；不改成任务失败，不重发管理请求。活动时间用原事件时间继续计算，不因新快照未带activity而变成从未提供；缺字段/断连称最后已知，新运行尚无事件称上次运行活动。从未观察过称尚未观察到活动，详情/tooltip解释原事件绝对时间和来源范围，不用心跳时间补活动。此副本仅当前App会话窗口的展示缓存，不持久化，不影响执行、未读、输入或验收。
- 新epoch：清掉旧可操作状态，重新获取capabilities；不保留可误点的旧运行对象。
- 未确认操作：展示unknown和原操作引用，给查询入口；没有证据不启用“自动重试”。
- Token partial：显示缺失范围/owner未覆盖数量，不写0。

## 7. 顶部展开与收起

compact/expanded为真正窗口状态，不是菜单弹窗；卡片、滚动及轻量输入只在展开态出现。离开延迟收起，pin或正在键盘编辑时不自动收起；Escape先退出编辑，再在非pin时收起，显式收起按钮可取消pin。仅用户点击输入才使panel获得键盘焦点；普通事件不弹主窗。所有展开/收起动效遵循Reduce Motion，主窗和顶部共用准确状态映射与管理路径。

参考CodeIsland的黑色顶部区域、卡片层级和节奏，但不复制其源码/角色/素材，不增加消息正文、工具参数、历史或LLM摘要来补视觉内容。原生预览使用显式合成fixture并禁用真实管理递送，不能把预览截图当实际owner闭环。

## 8. 三轮日常体验优化（2026-11-03 用户批准）

按下列顺序实现并逐轮验证，不增加模型调用、历史对话扫描、owner 自动轮询或强制 reload；不把本轮结束标为业务目标完成。

1. **会话与顶部速览**：默认紧凑、稳定列表；支持仅本机显示别名和用户主动置顶，名称不作为控制身份。主层只保留身份、执行状态和活动，完整技术依据留诊断。顶部优先实际待输入、已报告异常与置顶对象，展开编辑时不挪走正在操作的目标。验收覆盖同名、长名、64 条记录、断连与状态变化不重排。
2. **活动与提醒闭环**：新增可选的真实生命周期/工具事件时间标量，心跳不刷新活动时间，旧 bridge 缺字段保留未知。显示输入等待、本轮结束后的未查看变化；已查看不回答问题。最近操作及导航提示按准确 runtime 绑定，切换会话不串回执。验收覆盖心跳、agent_end/settled、pending、代际替换、断线及丢回执。
3. **层级与用量**：详情以当前状态、活动和主要操作为首屏，子任务/计划/用量/诊断按需展开；设置按本 App、Pi 原生、高级连接分层。提供同来源/同模型/同口径的前一等长日历时段对比，明确比较范围与缺失，不把未采集当零或把部分记录变化称为费用变化。验收覆盖 DST、缺桶、未知字段、快速切换和窄窗。

三轮定向及完整原生回归、59 项 bridge 测试与五组合成 SDK 检查已通过；64 条列表、重要事项、Token 和设置的深浅色合成窗口已真实渲染并读取截图。当前 Cua 后台 AX 无法绑定窗口，未据此宣称鼠标/键盘全控件交互通过；首次完整原生检查曾因旧增量产物 SIGBUS 失败，保留旧产物后全新构建恢复通过。

偏好复用既有私有 `app_view_state`，会话键以 hash 保存；别名仅为用户主动输入的有界本机显示文本，不采集对话。每轮保留定向回归，最终执行适用组合检查及合成原生预览；源码、安装、运行和正式发行分开声明。

## 9. 本轮交互与 AI 入口

- **通知与健康**：通知正文仍为通用文本，点击只按本机hash绑定的准确runtime定位。App冷启动最多等待接入一小段时间；旧epoch/超时显示原因，不按名字或cwd猜对象。接入健康将App连接、执行证明、原现场路由、采集、AI接口和系统通知分别呈现，只读投影不调用模型，刷新owner状态须明确用户操作。
- **草稿与命令**：⌘K搜索既有页面、会话、别名和工作组并执行固定动作；⌘4/⌘5打开健康/AI。面板打开时捕获准确目标，过期目标拒绝。草稿列表可复制或逐份明确丢弃；正常退出/更新有未发送正文（含AI补充）时默认取消退出并保留，不把文本写入usage库，不承诺崩溃恢复。
- **组织与顶部**：手动/AI采纳的工作组均仅本机标签（最多16组/64归属），按组筛选不会成为执行许可。顶部提供自动速览、仅菜单栏、默认固定展开；屏幕可跟随管理窗、主屏或指定屏，离线回退且不覆盖保存选择。隐藏面板不影响Pi、提醒或采集。
- **AI辅助**：进入AI页只读注册模型元数据，只有明确分析按钮才推理。默认8319的gpt-6.1-sol、medium可修改，不改业务Pi参数；优先读取本机Pi SDK注册表，不再要求旧会话先加载AI桥接；统一provider/model菜单和按模型能力的思考强度菜单保留可见标签，空目录明确不可用，不用只有当前配置的菜单冒充目录。缺少本机SDK仍可用兼容在线Pi入口；旧bridge对近期文本降级，不强reload。所选1–8个运行以Pi原生/name为主标题，项目/短ID辅助区分，不被Desk别名覆盖。原生改名事件与后续快照同步名称，缺失时明确显示未提供。“刷新名称”是显式一次性读取，旧bridge使用已有只读refresh（同时可能刷新owner状态），最多64个连接，沿已有节流，不自动轮询或重载。先显式读取有界当前分支近期用户/助手文本，允许完整展开预览/逐条移除；排除思考、工具消息、图片与疑似凭据，不扫历史。程序不保证识别所有敏感信息，发送前用户可检查范围。
- **AI结果与费用**：AI页分为“准备上下文 / AI建议与用量”两步，来源列表有界滚动，返回结果后在当前AI页切到建议区，不激活App或打断其他工作。总览/逐来源摘要/建议分组带输入引用、模型与完成时间，始终标为AI建议。无工具，不追加业务对话，不变更执行/输入/验收状态；仅用户采纳为本机标签，过时runtime禁用采纳。支持取消/超时与相同输入内存缓存，不静默换模/降档/重试；AI数值回执单列，不估账单，不保存原文。一次指定真实模型验真只用了合成上下文，其余测试均faux，不能写成所有测试零真实调用。

本轮回归覆盖真实Swift UDS下注册模型、近期上下文、推理/去重及业务历史/model/thinking不变；默认模型合成请求返回结构化结果。AI建议窄窗、接入健康、仅菜单栏设置和命令面板已有合成原生截图；后台AX绑定受限，不据此宣称新控件实际键鼠或VoiceOver全验。源码、精确head CI、合成渲染、实际安装及系统通知/键盘现场分别确认，不用其中一个替代其他证据。

## 10. Pi同源工作总览

新增“工作总览”（⌘6）与详情原生Todo清单，保留旧导航与用户页面偏好。按原生/name列准确session的当前步骤、计划已完成/进行中/未开始计数，依赖卡点和需用户输入分别筛选；内容懒加载、没有动态图表或额外推理。来源标识和最近任务更新时间可见，断连显示最后观测，未采集/旧bridge/partial都不冒充空清单。任务只读不能勾选完成，依赖提示是原blockedBy派生不是owner命令；输入正文未接时引导回准确原会话，不猜问题。首批不画虚构产品树，work/产品绑定缺口显式说明。

原问题有显式work关联时，在既有“等待你输入”卡片/详情/工作总览附原工作引用与阶段；未绑定或不可用如实显示，caller声明不等于认证。具体问题仍到原会话处理，不增加回答按钮。v1+新事件只1条输入/通知，附metadata不重置已读；closed/answer-received清理等待，但不改工作验收或权限。

### 工作卡片的摘要与来源

已有工作卡片分为“阶段、关联PR、记录head、等待来源、原已验记录、原下一步、需你处理”。没有原字段明确未提供；任务引用不冒充任务标题。PR只按原producer明确repository/pullRequest生成固定GitHub入口。结果与进度分别保留原时刻，非实时/失联明确标最后观测；较新unknown不被较早accepted覆盖，旧head与不同报告来源独立展示。

“需要你”筛选继续沿用现有真实输入语义：只有原生 `InputNotice` 明确声明同一 `workRef` 的工作卡才进入该筛选；未决决定、CI等待、owner对账或替换意向不会被升级成需要人工处理。筛选切换时工作卡片不消失，只按这个有来源的输入条件过滤；无匹配时明确显示未观察到绑定输入。

同完整binding/报告来源/epoch内的先前进度和结果折叠保留，四个unknown不会为了整齐变绿或消失；其他绑定也可展开。共享解释放在一次可展开状态说明，具体卡仅保留“仅子产物”“仅源码”等就地范围，不逐条重复整段技术免责声明。“来源绑定与原件引用”保留完整head/run/revision/session，来源会话/来源终端沿原准确路由，无原件URL不猜文件或命令。只有原生输入等待且声明同workRef才显示相关需用户事项，CI/Gate/交接建议不会创建审批。

### 消息传输关联

会话的原工作详情增加默认折叠的“消息传输关联”，仅显示该来源自然status查询的原生记录：消息ID、原替换/被替换/回复/迟答对应ID、原路由和原更新时间。只有原tool成功及最终结果一致才采集；没有数据明确未采集，不能显示为零。不同来源独立展示、不把消息归为任务，不添加回答/批准/撤销按钮或“需要我”提醒。matched仅表示broker回复匹配，late不等于业务答案作废，none不等于业务未答；旧broker/缺关系/冲突明确未知。

### 终端定位诊断稳定性

“原会话定位诊断”分别显示路由事实、最近权限检查、最近定位结果；后两项保留各自记录时间。路由存在不是权限/成功；普通快照不能把具体拒绝或上次失败改成泛化TTY提示。完整身份/运行代际、连接或路由改变时旧记录失效，显示当前上下文尚未检查/定位；来源非实时只读last-known，异步旧结果不跨到新上下文。下一步提示明确检查权限/按原检查处理授权/刷新定位，现有请求权限按钮仍只在用户主动点击时工作，不自动弹consent或重试焦点。

### 工作阅读和观察小结

工作卡用唯一明确的PR标识提高识别性，但不冒称原任务标题，完整引用可以展开；多个PR仍回退原引用。真实关联输入在阶段/记录之前，短head、原阶段/等待/下一步与来源仍保留，不把不同运行合成任务当前状态。重要事项逐条原输入可暂收起15分钟，显示已暂收起数量且可恢复；原问题和原通知仍在，本App退出不保留这项偏好。

工作总览“全部”增加默认折叠的当前观察小结，显示真实输入数量/已知最长等待、原工作来源覆盖和同一既有Token口径，提供明确点击后复制摘要及回原Token页。没有新模型/后台日报，复制时取当前同一portfolio/aggregate而非另存事实。摘要保留原引用/head/来源/原时间和仅阶段范围，窗口省略显式说明；不是完整全天结果、ROI或账单。业务价格/收益等缺原件就保持未提供。

### 原决策关闭与替换

复用原决策详情行，closed计数只称已记录关闭。原字段closeReason明确时分别标“收到答复记录”“原负责人撤回”“已被替换”；旧resolved无原因则明确未提供，不回填答复/批准。supersedes显示“替换意向”，仍须看旧项的原关闭记录；supersededBy只保留实际关闭时的精确新项ID。引用对象被预算省略不等于不存在或已关闭。没有新按钮、提醒、回答口、问题正文或自动授权；答复记录不判断语义有效性，撤回/替换也不撤销既有权限。

## 11. 原生实现验收

工作总览的“原 owner 工作结果”区收到显式Pi Vista观察或原生mission决策记录时出现；同一owner/kind/key可归组，但结果仍逐条显示stage/run/session/revision/head与观察来源。仅有决策记录时不补造结果行，各reporter的未决/已解决计数独立展示而不求和，原更新时间及非实时来源明确可见。产物可用、源码阶段交付、对账中、原生交接和下一步引用都带限定说明，不生成完成率，不把reconcile/wait变成“需要你”。没有Vista出口或旧bridge时显示来源未接入/未观察，不通过目录、名称、任务号或重复查询补齐。已有观察再读取超时则保留并明确“最近读取未确认”。工作总览保留已接入来源及其结果，不受会话页搜索/分组/隐藏断连卡片的本机列表偏好影响；隐藏卡片不会删除工作事实。

支持键盘导航、VoiceOver、动态文字、非颜色状态、减少动态效果、外接屏和无刘海屏；全屏/锁屏/显示器变化不阻塞主任务。不抢焦点，不自动打开控制面板盖住正在操作的应用。原生候选已有窗口/顶栏和AX控件，可用CUA在后台显示两个隔离SDK会话并提交native消息，界面保留requested而非假queued；空态、断联和提示也有实现。2026-10-29 用户现场确认通知可见、VoiceOver 能朗读并遍历会话列表及关键设置控件；该确认保留当时版本，不冒称全控件或新 build 全面重验。Herdr 正向实机与长期全组合仍未验证，缺路由按现有合同明确失败。静态预览只用于设计参照，不是运行证据。
