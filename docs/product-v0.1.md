# Pi Desk 首版产品范围

## 1. 用户结果

用户可以在一个原生入口看清已接入 Pi 会话、子任务、消耗和例外，并对原工作发出准确的管理请求；不用持续切换窗口，也不用守着界面让自动化继续。界面缺失、关闭或故障不改变原任务、通知兜底及权限。

需求依据是本次用户确认：只考虑 Pi；不需要各工具历史会话扫描；Pi Token 统计可以有；首版绝对不能降低 AI 自动化程度。2026-10-24 用户授权拉取新仓并规划架构、设计及实施方案，本轮不实现业务代码、不安装部署、不推送空仓 main。

## 2. 范围与完成标准

| 能力 | 首版承诺 | 不冒充的结果 |
|---|---|---|
| 在线会话 | 显式接入、准确身份、项目/分支/worktree摘要、模型/思考档、状态与工具名 | 没接入的会话不靠进程/文件扫描补齐；cwd 不证明实际影响仓 |
| 子任务 | 展示 owner 提供的父子/运行信息，支持其声明可用的管理动作 | 仅凭环境变量不覆盖进程内前台子任务；display key 不作为控制 runId |
| 会话管理 | 追加要求、steer/follow-up、请求中止当前回合，原终端/Herdr跳转 | 不直接写 stdin；中止回合不承诺取消队列、子任务或外部副作用 |
| 子任务管理 | 对准确运行对象纠偏、请求停止、符合 owner 条件时恢复 | 停止受理不等于进程终态；恢复不等于从头重跑 |
| 现有计划 | 按 owner 区分列表、状态、暂停/恢复/触发；缺接口补最小 adapter 或明确不可用 | 不新增任务库，不把 Schedule 与 Subagents 同名计划合并，不直接改 JSON |
| Token | 当前已接入会话的输入/输出/cache与子任务报告；明确 scope、coverage、时间和统计窗口 | 不做历史目录扫描、不承诺每日/全账户账单、不把未知标零 |
| 重要事项 | 实际待输入、失败、自动恢复、治理/Gate/CI摘要与来源 | 未读不等于未执行；Agent自报不等于测试/合并/部署验证 |
| 服务管理入口 | 可选连接现有管理系统并打开选定页面；必要受限动作复用原API | 服务未配置不影响会话功能；首版不复制整个管理后台 |

所有运行控制以当前加载的能力声明为准。v0.1 完整验收包含非只读管理闭环；早期 M1 观察里程碑不能单独标记 v0.1 交付。

## 3. 不退化不变量

1. 在相同任务、原授权/策略、模型/思考档/工具/资源和输入下，新增人工确认数为 0。
2. 展示和健康检查不触发模型回合，不修改 prompt、active tools、原自动重试/压缩/调度/回传。
3. 客户端进程不是 Pi 的 parent/supervisor。断联、退出、更新或显示队列拥塞不发送 abort/shutdown。
4. 观察失败只降级观察；具体管理请求无权限/无接口时只拒绝该请求，不全局暂停自动化。
5. 既有 AI/CLI/工具管理路径保持可用。GUI 不成为新许可源，也不替代 owner 硬规则。
6. 用户明确操作造成的改变与系统隐式退化分开；关闭提醒不回答问题，关闭卡片不停止工作。
7. 不以审批全自动点击、全局 bypass 或改权限来声称自动化程度不降低。

## 4. 统计与无历史扫描的边界

“无历史扫描”禁止发现/遍历/解析会话目录、旧 JSONL、rollout、终端内容、认证与模型配置。可以在已接入 owner 内访问其已加载对象的 usage 标量/原生统计结果；不能让 App 打开原始会话文件。

- 普通 TUI 扩展首先提供 `attachment-window`：从本次扩展接入起观测到的已结算 usage，重载后新窗口明确重置。
- owner 可提供原生当前会话累计时，另列 `native-session-total`，不能把接入窗口值标成会话全部消耗。
- Subagents `cost` 存在既有当前分支/关联 run artifact 读取行为，可在用户已确认的 Pi 统计范围内复用，无需增加逐项批准；标明 owner-reported 来源、当前会话范围和不完整覆盖。无历史扫描不等于底层 owner 零文件读取：禁止的是 Pi Desk 广泛发现旧会话或自行解析原文件，不禁止原 owner 读取当前关联运行的统计产物。
- 父子总数只有在 owner 给出明确、不重叠的归属和覆盖时展示；同一子任务独立卡片不再次计入汇总。
- 接入窗口、会话累计、上下文占用是不同量，不直接相加；切换模型仍按来源维度保留。
- 没有费用来源就不显示价格估算。成本 unknown 不代表免费。

## 5. 非目标

其他 AI 工具；任何历史会话发现/导入；新 Agent宿主/执行器/调度器/任务库；自动审批或新LLM judge；任意shell/任意工具代理；重建终端/SSH/凭据库；批量修改全局Pi设置；强制旧会话reload；手机/Watch/ESP32；多角色动画与大规模外观系统；全账户/全历史计费统计。

## 6. 用户验收路径

- 启动现有已授权 Pi，显式加载薄扩展。App可展示它，但不额外发起模型请求。
- 在至少两个合成会话及前台/后台子任务组合中验证身份、管理目标、回传与Token覆盖。
- 在界面发 follow-up/steer，回到原会话确认消息进入原生路径；无关联原生收据时界面只显示已请求，有证据才显示已确认排队，不伪造完成。
- 请求中止当前回合/停止一个子任务，显示请求与终态证据；其他会话继续运行。
- 退出、重启、强制结束 App，原自动重试、计划、子任务和消息回传继续；重连读取当前快照而不重放控制。
- 产生真实待输入生命周期与合成治理/CI变化，关闭提醒不影响原问题和任务。
- 比较关闭/接入两组相同fixture的执行轨迹、模型调用数、人工确认数、原参数及额外开销。

本轮仅验证文档、spec与静态合成设计，不执行上述业务或真实会话验收。规范要求见单一 Change 的 [live-pi-sessions](../openspec/changes/pi-desk-v0-1/specs/live-pi-sessions/spec.md)、[owned-management](../openspec/changes/pi-desk-v0-1/specs/owned-management/spec.md)、[usage-and-attention](../openspec/changes/pi-desk-v0-1/specs/usage-and-attention/spec.md)。
